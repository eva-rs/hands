# eva-hands

Руки Евы на рабочей машине: демон, который делает с файлами и процессами
то, что ядро до него делало шелл-однострочниками через `ssh`.

Демон и клиентская библиотека живут в одном ящике: `eva-hands` — бинарь,
`eva_hands` — крейт, который подключает ядро.

## Зачем

Ядро правило удалённую машину так: на каждую операцию поднимался `ssh`,
содержимое возилось base64 через `cat`/`dd`/`tail`/`head`, а поиск образца
шёл потоком по ssh-трубе, потому что `grep` построчный и в двоичном файле
«строка» бывает во весь файл. Отсюда четыре беды:

- **рукопожатие на каждый чих** — секунда ssh на каждое чтение;
- **зависимость от утилит той стороны** — `dd oflag=seek_bytes`, `base64 -w0`
  есть не везде, и флаги у них разные;
- **код возврата в конвейере принадлежит последней команде** — пропавший
  файл выглядел пустым;
- **гигабайты по проводу** — поиск в архиве визуальной новеллы тянул через
  ssh весь файл, чтобы найти в нём четыре байта.

eva-hands закрывает всё четыре: соединение одно и долгое, байты едут сырьём,
у каждого отказа свой код, а файл читает та машина, где он лежит.

## Транспорт: ssh + stdio

Демон запускается **самой ssh-сессией** — `ssh <машина> eva-hands serve` —
и говорит своим протоколом по её stdin/stdout. Клиент поднимает такую
сессию один раз и гоняет по ней все операции.

Почему так, а не иначе:

| вариант | что даёт | чем плох |
| --- | --- | --- |
| **ssh + stdio (выбран)** | доступ решают уже существующие ключи; нового открытого порта нет; соединение одно на всё | сессия живёт, пока жив клиент |
| свой TCP с аутентификацией по ssh-ключам | не нужен ssh на машине клиента | лишний открытый порт, свой разбор ключей, своё рукопожатие и свой шифр — то есть свой класс дыр |
| ssh forced-command | ключ не может ничего, кроме рук | у ядра **один** ключ и на `shell`, и на руки: запереть его на forced-command значит отобрать `shell` |

Ключевое: доступ и так был — ядро ходит на эту машину по ssh и исполняет
там команды. eva-hands не расширяет права, он меняет способ разговора.
Открытый TCP-порт добавил бы новую поверхность ради удобства, которого
хватает и так.

**Про forced-command.** Запереть ключ записью
`command="eva-hands serve",restrict <ключ>` — правильная защита, но
работает она, только если у ядра для рук **отдельный** ключ: тот же ключ
нужен ему для `shell`. Модуль умеет это (`services.eva-hands`), но по
умолчанию не делает — это решение хозяина машины.

**Резидентный демон** нужен ровно в одном случае: клиент на этой же машине
хочет говорить с руками, живущими под своим юнитом (свой пользователь,
свои лимиты systemd). Для этого есть `eva-hands daemon --listen <сокет>`.
Для ssh-пути он не нужен и по умолчанию не поднимается: там демон живёт
ровно столько, сколько живёт соединение.

Когда машина своя, соединения нет вовсе: `Hands::local` исполняет те же
операции прямо в процессе. Одна реализация на оба случая — ветка «локально
через `std::fs`, удалённо через шелл» разошлась бы на первой же правке.

## Протокол

Кадр — две длины, JSON-шапка и **сырое тело**:

```
u32 header_len | u32 body_len | header (JSON) | body (bytes)
```

Содержимое файлов едет телом, мимо JSON: base64 раздувает вчетверо и
заставляет обе стороны держать лишнюю копию.

У каждого запроса `id`, ответы приходят **в любом порядке**: по одному
соединению идёт вся работа сразу, и минутная команда не запирает чтение
файла. Рабочий каталог (`cwd`) — поле запроса, а не состояние сессии:
состояние на общем соединении — это гонка между чатами, у каждого из
которых свой каталог.

Первым кадром демон здоровается: версия протокола, версия демона, имя
хоста и потолки машины. Отсюда две выгоды — расходящиеся версии видны
сразу, а не посреди разговора; и если рук на машине нет, клиент получает
не молчание, а `eva-hands: command not found` из stderr ssh.

### Операции

Были в ядре и переехали как есть:

| операция | что делает |
| --- | --- |
| `read` | кусок файла (или файл целиком) плюс полная длина |
| `stat` | в т.ч. длина файла |
| `write` | файл целиком |
| `write_at` | байты по смещению, с усечением или без |
| `find` | смещения вхождений образца |
| `exec` | команда с таймаутом |

Добавлены — и вот зачем:

| операция | зачем |
| --- | --- |
| `list` | без списка каталога разбор чужого дерева (движок новеллы, чужой репозиторий) начинается с `ls` через шелл — то есть с того, от чего уходим |
| `stat` (тип, права, mtime, цель симлинка) | «файл или каталог», «исполняемый ли», «свежее ли распакованного» — вопросы каждого второго шага реверса; раньше на них отвечал `stat`/`file` в шелле, по-разному на разных системах |
| `mkdir`, `rename`, `remove` | распаковать, переименовать, убрать за собой. `rename` вдобавок единственный способ подменить файл, не потеряв его при обрыве |
| `ping` | простаивающая ssh-труба умирает молча; спросить дешевле, чем узнать посреди работы |

Сознательно **не** добавлено: рекурсивный обход, глоб, чтение построчно,
хеши. Обход и глоб — это `exec` с `find`/`rg`, они уже есть и делают это
лучше; построчность и хеши живут в ядре, которое и так режет файл на окна.

### Коды отказов

`not_found`, `not_a_file`, `not_a_dir`, `denied`, `too_large`, `timeout`,
`invalid`, `unsupported`, `io`. Код нужен, чтобы спрашивающий отличал
«файла нет» от «слишком велик» — и не выдавал пустоту за содержимое.

Клиент делит отказы надвое: **операция не удалась** (это ответ машины,
врать поверх него нельзя) и **руки недоступны** (демона нет, соединение
оборвалось — можно пойти другим путём). Ядро на второй ветке возвращается
к шелл-однострочникам.

## Что бережно перенесено

- **Потоковый поиск с перекрытием окна.** Файл течёт мимо кусками по
  мегабайту, окно перекрывается на длину образца без единицы — иначе
  вхождение на стыке потерялось бы. Архивы визуальных новелл бывают на
  гигабайты, в память их класть нельзя.
- **Обрыв чтения по лимиту находок** — искомое обычно в начале, тянуть
  остаток файла незачем; ответ честно говорит `stopped`.
- **Неинтерактивное окружение команд**: `PAGER=cat`, `TERM=dumb`,
  `GIT_TERMINAL_PROMPT=0`, `NO_COLOR`, `DEBIAN_FRONTEND=noninteractive`.
  Программа, решившая, что перед ней терминал, висит до самого таймаута.
- **Честные ошибки вместо пустого ответа** — теперь кодом, а не угадыванием
  по тексту.
- **Потолки на объём** — `max_read`, `max_write`, `max_hits`, `max_output`.

Чего у ядра не было и что появилось здесь:

- **Атомарная запись.** Файл целиком пишется в соседний временный файл,
  синхронизируется и подменяется `rename`. Оборванная запись оставляла
  обрубок вместо прежнего содержимого. Права существующего файла переживают
  замену. Запись по смещению атомарной быть не может — это правка на месте,
  и так и задумано.
- **`~` разворачивается.** Путь, ушедший в шелл в кавычках, оставался
  тильдой как есть, и файл не находился по вине кавычек.
- **Изгородь корней** (`roots`): путь разбирается лексически (`..`
  схлопывается) и обязан лежать внутри разрешённых. Это грубая изгородь, а
  не песочница — симлинки она не отслеживает.

## Настройка

`/etc/eva-hands.toml` (или `--config`); всё необязательно.

```toml
max_read = 67108864             # сколько байт отдаём за одно чтение
max_write = 268435456           # сколько принимаем за одну запись
max_hits = 4096                 # потолок находок и записей каталога
max_output = 1048576            # символов на поток вывода команды
exec = true                     # false — руки остаются файловыми
exec_timeout_secs = 60          # если спрашивающий не назвал свой
exec_max_timeout_secs = 3600    # потолок таймаута
roots = []                      # пусто — вся файловая система
```

Потолки уезжают клиенту в рукопожатии: зная их, он откажет сам и не
потащит по проводу то, что всё равно не примут.

## Развёртывание

Флейк даёт пакет и NixOS-модуль:

```nix
{
  inputs.eva-hands.url = "git+https://git.desu.church/eva/hands.git";

  # в конфигурации машины
  imports = [ inputs.eva-hands.nixosModules.default ];
  services.eva-hands = {
    enable = true;
    settings = {
      exec = true;
      roots = [ ];
    };
  };
}
```

Модуль кладёт пакет в системный профиль (ssh зовёт `eva-hands serve` голым
именем — без профиля неинтерактивная сессия его не найдёт) и пишет
`/etc/eva-hands.toml`. Юнита при этом не появляется: по ssh демон
запускается сессией. Юнит поднимается только если задать `socket` —
резидентный демон на юникс-сокете для клиента с этой же машины.
